Algoritmo

Un algoritmo es un conjunto ordenado, finito y definido de instrucciones o reglas paso a paso que permiten solucionar un problema, realizar un cómputo o procesar datos. Funciona recibiendo datos de entrada (input), procesándolos mediante reglas lógicas y produciendo un resultado final (output). Son la base de la programación y la tecnología moderna.

Realice un algoritmo llamado “calculodegalones” que tiene como propósito convertir la producción diaria ingresada en litros a su equivalente en galones y, a partir de ello, calcular el monto total a cobrar según un precio por galón. Primero se definen las variables necesarias para almacenar los datos de entrada y los resultados, luego se solicita al usuario que ingrese la cantidad de litros producidos y el precio por galón. Posteriormente, en el proceso, se realiza la conversión de litros a galones utilizando el factor 3.785 y se calcula el total a pagar multiplicando los galones obtenidos por el precio ingresado. Finalmente, el algoritmo muestra en pantalla los resultados, es decir, la cantidad equivalente en galones y el total a cobrar, permitiendo así obtener de forma sencilla tanto la conversión de unidades como el cálculo económico correspondiente.

Pseudocódigo

El pseudocódigo es una forma de representar algoritmos y la lógica de programación utilizando una mezcla de lenguaje natural (español) y estructuras de código, sin las reglas sintácticas estrictas de un lenguaje real. Sirve como borrador para planificar programas, enfocándose en el flujo lógico antes de la codificación.

En este caso presentamos el algoritmo de “calculodegalones”:

Algoritmo calculodegalones

    Definir litros, precioPorGalon Como Real
    Definir galones, totalACobrar Como Real

    Escribir "Ingrese la producción del día (en litros):"
    Leer litros

    Escribir "Ingrese el precio por galón ($):"
    Leer precioPorGalon

    galones <- litros / 3.785
    totalACobrar <- galones * precioPorGalon

    Escribir "----- Resultados -----"
    Escribir "Equivalente en galones: ", galones, " galones"
    Escribir "Total a cobrar: $", totalACobrar

FinAlgoritmo

Diagrama de flujo

Un diagrama de flujo (o flujograma) es una representación gráfica de un proceso, algoritmo o sistema, que utiliza símbolos estandarizados conectados por flechas para secuenciar pasos. Permite visualizar de forma clara y ordenada acciones, decisiones y el flujo de información desde el inicio hasta el final de una tarea.

Prueba de escritorio

Una prueba de escritorio es la simulación manual y paso a paso de un algoritmo, pseudocódigo o código, utilizando papel y lápiz (o una tabla) para rastrear los valores de las variables y verificar la lógica sin ejecutarlo en la computadora. Es fundamental para detectar errores tempranos, validar la funcionalidad y entender el flujo del programa.

Lenguajes de programación

Los lenguajes de programación son sistemas formales utilizados para dar instrucciones a las computadoras, divididos principalmente en alto nivel (cercanos al humano) y bajo nivel (cercanos al hardware). Los más populares y utilizados incluyen Python (versátil), JavaScript (desarrollo web), Java (empresarial), C# (videojuegos) y C/C++ (rendimiento).

En clase usamos el lenguaje C en Visual Studio porque te permite entender las bases fundamentales de la programación, como el manejo de memoria, estructuras de control y lógica computacional de forma clara y directa. C es un lenguaje de bajo nivel comparado con otros, así que te obliga a comprender cómo funciona realmente el computador, lo cual fortalece tus habilidades para aprender otros lenguajes más fácilmente. Además, Visual Studio ofrece herramientas como depuración paso a paso y autocompletado que facilitan el aprendizaje, ayudándote a detectar errores y mejorar tu código de manera más rápida y profesional.

Mi pseudocódigo transformado en lenguaje C:

#include <stdio.h>

int main() {
    float litros, precioPorGalon;
    float galones, totalACobrar;

    printf("Ingrese la producción del día (en litros): ");
    scanf("%f", &litros);

    printf("Ingrese el precio por galón ($): ");
    scanf("%f", &precioPorGalon);

    galones = litros / 3.785;
    totalACobrar = galones * precioPorGalon;

    printf("\n----- Resultados -----\n");
    printf("Equivalente en galones: %.2f\n", galones);
    printf("Total a cobrar: $ %.2f\n", totalACobrar);

    return 0;
}

Programación por bloques

La programación por bloques es un método visual para crear software arrastrando y encajando piezas gráficas (bloques) que representan comandos, eliminando la necesidad de escribir sintaxis compleja. Es ideal para principiantes y niños, ya que permite aprender lógica de programación secuencial de forma intuitiva, lúdica y sin errores de escritura.

Este tipo de ejercicios es muy útil para desarrollar la lógica básica de programación, ya que permite enfocarse en la correcta comprensión de las variables, operaciones y entrada/salida de datos. Además, sirve como base fundamental antes de avanzar hacia estructuras más complejas como las condicionales y los ciclos, que requieren un mayor nivel de razonamiento y control del flujo del programa.

Estructuras condicionales

Las estructuras condicionales permiten que un programa tome decisiones según una condición. Es decir, el programa evalúa si algo es verdadero o falso y, dependiendo del resultado, ejecuta una acción.

Ejercicio: Control de ventas en una tienda

Planteamiento del problema

Se desea crear un programa que permita ingresar la cantidad de productos vendidos en una tienda. Por cada producto se debe ingresar su precio. Si el precio es menor o igual a 0, el programa debe mostrar un mensaje de error y volver a pedir el dato.

Al final, el programa debe calcular el total de la venta. Si el total supera los $100, se aplica un descuento del 10%. Caso contrario, no se aplica descuento.

Análisis del problema
ElementoDescripción
Datos de entradaCantidad de productos vendidos, precio de cada producto.
Proceso1. Solicitar la cantidad de productos.
2. Validar que los productos sean mayores que 0.
3. Solicitar el precio de cada producto.
4. Validar que cada precio sea mayor que 0.
5. Acumular el total de las ventas.
6. Verificar si el total supera los $100.
7. Si supera los $100, calcular un descuento del 10%; caso contrario, descuento igual a 0.
8. Calcular el total final a pagar.
Datos de salidaTotal de la venta, descuento aplicado y total final a pagar.
Diseño del algoritmo (Diagrama de Flujo)
Codificación
#include <stdio.h>

int main() {

    int cantidadProductos, i;
    float precio, total = 0;
    float descuento, totalFinal;

    // Ingreso y validación de la cantidad de productos
    do {
        printf("Ingrese la cantidad de productos vendidos: ");
        scanf("%i", &cantidadProductos);

        if (cantidadProductos <= 0) {
            printf("Ingrese una cantidad mayor que 0\n");
        }
    } while (cantidadProductos <= 0);

    // Ingreso y validación de precios
    for (i = 1; i <= cantidadProductos; i++) {
        do {
            printf("Ingrese el precio del producto #%i: ", i);
            scanf("%f", &precio);

            if (precio <= 0) {
                printf("Ingrese un precio valido\n");
            }
        } while (precio <= 0);

        total = total + precio;
    }

    // Aplicación del descuento
    if (total > 100) {
        descuento = total * 0.10;
    } else {
        descuento = 0;
    }

    // Cálculo del total final
    totalFinal = total - descuento;

    // Resultados
    printf("\nTotal sin descuento: $%.2f\n", total);
    printf("Descuento aplicado: $%.2f\n", descuento);
    printf("Total a pagar: $%.2f\n", totalFinal);

    return 0;
}

Una de las principales dificultades fue identificar correctamente cuándo usar una estructura condicional y cuándo usar una estructura repetitiva. Contenidos

Modularidad

1. Concepto e importancia

La modularidad consiste en descomponer un programa grande en unidades más pequeñas llamadas módulos. En C, la unidad modular básica es la función. Cada función debe realizar una tarea concreta y comunicarse con otras funciones mediante parámetros y valores de retorno. En proyectos mayores, la modularidad también se expresa separando declaraciones en archivos de cabecera (.h) e implementaciones en archivos fuente (.c).

  • Facilita la lectura del código, porque cada función representa una operación específica.
  • Favorece la reutilización, ya que una función bien diseñada puede utilizarse en diferentes partes del programa.
  • Simplifica las pruebas y la corrección de errores al permitir revisar cada módulo por separado.
  • Reduce la repetición de instrucciones y mejora el mantenimiento del software.
  • Permite distribuir el trabajo entre varios programadores cuando el proyecto se divide en archivos y responsabilidades.

Una función en C posee un tipo de retorno, un nombre, una lista de parámetros y un cuerpo. El prototipo informa al compilador sobre la firma de la función antes de que sea llamada. Cuando no existe un valor de retorno se utiliza el tipo void. Las variables declaradas dentro de una función son locales y solamente existen dentro de su bloque; en cambio, las variables globales pueden ser accedidas desde varias funciones, aunque su uso excesivo aumenta el acoplamiento y dificulta el control del programa.

Ejemplo 1. Estructura básica de un programa modular

#include <stdio.h>

int sumar(int a, int b);

int main(void) {
    int resultado = sumar(8, 5);
    printf("Resultado: %d\n", resultado);
    return 0;
}

// Definición del módulo
int sumar(int a, int b) {
    return a + b;
}

En el ejemplo anterior, main coordina la ejecución y la función sumar resuelve una tarea específica. Esta separación hace que el programa sea más fácil de comprender y permite reemplazar o probar la operación de suma sin modificar toda la lógica principal.

2. Pase de parámetros por valor y mediante punteros

En el paso por valor, una función recibe copias de los datos enviados y cualquier cambio realizado dentro de ella no modifica las variables originales. En cambio, cuando se envía la dirección de una variable mediante un puntero, la función puede acceder al dato original y modificarlo. En C, esta segunda técnica suele llamarse “paso por referencia”, aunque técnicamente la dirección también se transmite por valor.

Problema aplicado: cálculo de una compra con descuento

Una tienda necesita calcular el total de una compra. El usuario debe ingresar la cantidad de productos, el precio unitario y el porcentaje de descuento. El descuento se calculará mediante una función que reciba los datos por valor. Después, otra función recibirá la dirección del total y lo modificará directamente para aplicar el descuento.

Análisis del problema
ElementoDescripción
Datos de entradaCantidad de productos, precio unitario y porcentaje de descuento.
ProcesoCalcular el subtotal, obtener el descuento por valor y actualizar el total mediante un puntero.
Datos de salidaSubtotal, descuento calculado y total final de la compra.
Pase por valorcalcularDescuento recibe copias del subtotal y del porcentaje.
Pase mediante punteroaplicarDescuento recibe la dirección de total y modifica su contenido.
Solución en lenguaje C
#include <stdio.h>

float calcularDescuento(float subtotal, float porcentaje) {
    return subtotal * porcentaje / 100.0f;
}

void aplicarDescuento(float *total, float descuento) {
    *total = *total - descuento;
}

int main(void) {
    int cantidad;
    float precioUnitario;
    float porcentajeDescuento;
    float subtotal;
    float descuento;
    float total;

    printf("Ingrese cantidad de productos: ");
    scanf("%d", &cantidad);

    printf("Ingrese precio unitario: ");
    scanf("%f", &precioUnitario);

    printf("Ingrese porcentaje de descuento: ");
    scanf("%f", &porcentajeDescuento);

    if (cantidad <= 0 || precioUnitario <= 0 ||
        porcentajeDescuento < 0 || porcentajeDescuento > 100) {
        printf("Datos no validos.\n");
        return 1;
    }

    subtotal = cantidad * precioUnitario;

    /* Pase por valor: la función recibe copias de los datos. */
    descuento = calcularDescuento(subtotal, porcentajeDescuento);

    total = subtotal;

    /* Pase mediante puntero: se modifica directamente total. */
    aplicarDescuento(&total, descuento);

    printf("\nSubtotal: $%.2f\n", subtotal);
    printf("Descuento calculado: $%.2f\n", descuento);
    printf("Total final: $%.2f\n", total);

    return 0;
}

Arreglos en C

Un arreglo es una colección de elementos del mismo tipo almacenados en posiciones contiguas de memoria. Cada elemento se identifica mediante un índice entero. En C, el primer índice es 0 y el último es tamaño - 1. El lenguaje no comprueba automáticamente si un índice se encuentra dentro de los límites válidos, por lo que el programador debe controlar cuidadosamente los recorridos [3], [4].

Regla esencial: Para un arreglo declarado como int datos[5], los índices válidos son 0, 1, 2, 3 y 4. Acceder a datos[5] queda fuera del arreglo y produce comportamiento indefinido.
1. Tipos de arreglos

Arreglo unidimensional: organiza datos en una sola secuencia y se utiliza para listas de notas, edades, temperaturas o precios.

Arreglo bidimensional: utiliza filas y columnas, por lo que permite representar tablas, matrices o calificaciones de varios estudiantes en diferentes materias.

Arreglo multidimensional: posee tres o más índices y puede representar conjuntos de matrices, capas o información organizada en varias dimensiones.

Problema aplicado: control de calificaciones de estudiantes

Se necesita desarrollar un programa que registre las calificaciones de tres estudiantes en tres materias. El programa debe validar que cada nota se encuentre entre 0 y 100, calcular el promedio de cada estudiante y determinar quién obtuvo el promedio más alto. Para resolverlo se utilizará una matriz para almacenar las notas y un arreglo unidimensional para guardar los promedios.

Análisis del problema
ElementoDescripción
Datos de entradaNueve calificaciones: tres notas para cada uno de los tres estudiantes.
Estructuras utilizadasUna matriz notas[3][3] y un vector promedios[3].
ProcesoValidar las notas, sumar cada fila, calcular los promedios y comparar los resultados.
Datos de salidaPromedio de cada estudiante y estudiante con el promedio más alto.
Solución en lenguaje C
#include <stdio.h>

#define ESTUDIANTES 3
#define MATERIAS 3

int main(void) {
    float notas[ESTUDIANTES][MATERIAS];
    float promedios[ESTUDIANTES];
    int mejorEstudiante = 0;

    for (int i = 0; i < ESTUDIANTES; i++) {
        float suma = 0.0f;

        printf("\nEstudiante %d\n", i + 1);
        for (int j = 0; j < MATERIAS; j++) {
            do {
                printf("Ingrese la nota %d: ", j + 1);
                scanf("%f", &notas[i][j]);

                if (notas[i][j] < 0 || notas[i][j] > 100) {
                    printf("La nota debe estar entre 0 y 100.\n");
                }
            } while (notas[i][j] < 0 || notas[i][j] > 100);

            suma += notas[i][j];
        }

        promedios[i] = suma / MATERIAS;
    }

    for (int i = 1; i < ESTUDIANTES; i++) {
        if (promedios[i] > promedios[mejorEstudiante]) {
            mejorEstudiante = i;
        }
    }

    printf("\nRESULTADOS\n");
    for (int i = 0; i < ESTUDIANTES; i++) {
        printf("Estudiante %d - Promedio: %.2f\n",
               i + 1, promedios[i]);
    }

    printf("Mejor promedio: Estudiante %d con %.2f\n",
           mejorEstudiante + 1, promedios[mejorEstudiante]);

    return 0;
}

Principales dificultades y reflexión crítica en la aplicación de los contenidos

4. Principales dificultades

Interpretar correctamente el “paso por referencia”. La expresión es útil pedagógicamente, pero puede ocultar que C continúa pasando por valor. Lo que se copia es la dirección. Comprender esta precisión ayuda a razonar sobre punteros, alias y efectos laterales.

Controlar los límites de los arreglos. C no impide automáticamente acceder a una posición inválida. Un ciclo con la condición i <= tamaño provoca una iteración adicional; la condición correcta suele ser i < tamaño. Este error puede alterar memoria ajena al arreglo.

Comunicar el tamaño a las funciones. Cuando un arreglo se pasa a una función, normalmente se convierte en un puntero a su primer elemento y la función no conoce por sí sola la cantidad de elementos. Por ello se debe enviar también el tamaño o emplear una convención clara.

Diseñar módulos equilibrados. Dividir demasiado el programa puede producir muchas funciones pequeñas sin valor real, mientras que dividir poco genera funciones largas y difíciles de probar. El reto consiste en encontrar responsabilidades coherentes y una interfaz clara.

5. Reflexión crítica

La aplicación de la modularidad demuestra que programar no consiste únicamente en obtener una salida correcta. Un programa puede funcionar y, aun así, ser difícil de leer, probar o modificar. La calidad mejora cuando las funciones poseen nombres descriptivos, parámetros necesarios, pocas dependencias globales y un propósito claramente delimitado. No obstante, la modularidad también exige planificación: una división artificial o excesiva puede aumentar la cantidad de interfaces y hacer más difícil seguir el flujo de ejecución.

Los arreglos, por su parte, ofrecen eficiencia y una representación compacta de datos homogéneos. Su cercanía con la memoria es una ventaja formativa porque permite comprender índices, direcciones y recorridos. Al mismo tiempo, esa libertad implica responsabilidad: el lenguaje confía en que el programador respete los límites y mantenga coherencia entre el tamaño declarado y el tamaño utilizado. Esta característica explica por qué muchos errores en C no son errores sintácticos, sino fallos lógicos o de memoria.

La relación entre ambos contenidos es directa. Los arreglos adquieren mayor utilidad cuando se procesan mediante funciones especializadas: leer, mostrar, ordenar, buscar, sumar o calcular estadísticas. Para hacerlo correctamente, la interfaz de cada función debe indicar el tipo de los elementos, el tamaño y, en matrices, las dimensiones requeridas. Por tanto, el dominio de arreglos depende en gran medida de una comprensión sólida de funciones y punteros.

Una práctica crítica y responsable consiste en compilar con advertencias activadas, validar entradas, evitar constantes numéricas repetidas, documentar precondiciones y probar casos límite. Por ejemplo, deben probarse arreglos vacíos cuando el diseño lo permita, tamaños mínimos, valores repetidos, cadenas cercanas al límite y punteros potencialmente nulos. De esta manera, el aprendizaje pasa de memorizar sintaxis a construir soluciones confiables.

Conclusiones, bibliografía y declaración general

Conclusiones generales

La elaboración de este portafolio digital permitió integrar de manera progresiva los aprendizajes desarrollados en las tres unidades de la asignatura de Teoría de la Programación. En la primera unidad se fortaleció la comprensión de los algoritmos, el pseudocódigo, los diagramas de flujo y las pruebas de escritorio como herramientas fundamentales para analizar problemas antes de escribir un programa. En la segunda unidad se aplicaron estructuras secuenciales, condicionales y repetitivas, comprendiendo cómo un programa puede tomar decisiones, validar información y ejecutar procesos de forma controlada. Finalmente, en la tercera unidad se profundizó en la modularidad, el uso de funciones, el pase de parámetros y el manejo de arreglos en lenguaje C.

El conjunto de actividades evidencia que programar no consiste únicamente en conocer instrucciones o sintaxis, sino en desarrollar una forma ordenada de razonar, dividir problemas complejos y comprobar que las soluciones funcionen correctamente. La práctica con funciones y arreglos permitió reconocer la importancia de escribir programas legibles, reutilizables y fáciles de mantener, mientras que el estudio de las estructuras de control reforzó la capacidad para construir soluciones lógicas y eficientes.

La presentación del trabajo mediante una página web publicada con GitHub complementa los conocimientos de programación con habilidades de organización, documentación y comunicación digital. En conclusión, este portafolio demuestra un avance integral en el análisis de problemas, el diseño de algoritmos, la programación en C y la presentación responsable de evidencias académicas, constituyendo una base sólida para continuar con asignaturas y proyectos de mayor complejidad.
